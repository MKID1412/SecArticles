#  三个已修复的洞，我照着公告复现了一遍  
原创 夜游神
                    夜游神  船山信安   2026-11-23 16:00  
  
漏洞挖掘 · VULNHUNT  
  
三个已修复的洞，我照着公告复现了一遍  
  
  
补笔记的时候顺手复现了三个老洞。都出了修复版本，所以把过程写下来。  
  
重点不是怎么打，是为什么会有、怎么发现、怎么修。  
  
以下漏洞均已有官方修复版本，本文只做原理与检测复盘，不提供针对未修复系统的利用步骤。  
  
第一个：配置没关，谁都能进  
  
某后台管理组件，早期版本默认开放了注册接口，且没做鉴权。原理很简单：本该只在初始化时调用的接口，被永久留在了对外服务里。

检测思路就一条：先看版本，再看那个接口是不是还开着。别拿扫描器的可能存在的结论当事实，手动确认一次只要十秒。  
  
第二个：反序列化，入口在看起来无害的参数  
  
某 Java 组件把用户输入的对象直接反序列化了。这类问题的共同点是：信任了本不该信任的序列化数据。  
  
复现时我卡在版本判断上——同一组件不同版本入口不一样。后来发现响应头里的构建号能区分，这才对上号。  
  
复现老洞最费的往往不是利用，是确认你面对的到底是哪个版本。  
  
修复方面，官方出了新版本；临时缓解可以限制相关接口的访问来源，但升级才是根本。  
  
第三个：模板渲染把用户输入当代码  
  
某报表工具在渲染模板时，把用户可控的字段拼进了表达式里，导致表达式被执行。  
  
1  
先确认版本，只在对自己有授权的环境里做  
  
2  
看接口文档，找哪些参数会进模板引擎  
  
3  
只验证表达式是否被求值，不做进一步利用  
  
修法是升级加对用户输入做白名单，别试图用黑名单挡表达式——挡不住。  
  
复现老洞的正确姿势  
  
·  
先查官方公告和修复版本，确认它不是在野未修复的洞  
  
·  
只在对自己有授权的环境复现，不扫互联网上的真实资产  
  
·  
记录重点放在版本怎么确认、根因是什么、怎么修，而不是利用细节  
  
这三个洞放一起看，根因其实就两类：不该开的没关，不该信的信了。
