#  11年前的Linux内核TCP漏洞NoisyTCP允许黑客无需身份验证即可远程瘫痪服务器  
ZM
                    ZM  暗镜   2026-11-22 22:00  
  
Linux 内核 TCP 漏洞存在长达 11 年之久，一直未被发现，远程攻击者无需凭证即可使服务器崩溃。研究员 Hyunwoo Kim (@v4bel) 发现了该漏洞并进行了修复。他将其命名为 NoisyTCP，并将其追踪为 CVE-2026-99288。在与 Linux 发行版约定的禁令结束后，Kim在 oss-security 邮件列表中发布了完整的安全公告。他将其描述为内核 TCP 协议栈中一个预认证远程数据损坏漏洞。  
  
当前问题是竞争条件。过期的已建立哈希（ehash）查找必须与释放和重新分配现有请求套接字同时发生，并且这些操作必须在不同的接收（RX）上下文中进行。Kim 表示，攻击者可以将数据包处理分布到多个 CPU 上，因为 IPv4 分片和标准 TCP 数据包会生成不同的接收哈希值。此漏洞会影响具有两个或多个接收队列的服务器，或者使用接收数据包转向 (RPS) 将数据包分散到多个 CPU 的服务器。攻击者只需访问一个标准的 TCP 监听器即可，因此默认的 Nginx、Apache 和 SSH 服务器尤其容易受到攻击。  
  
在第一种触发场景中，过期的查找结果识别出一个请求套接字，而另一个接收上下文则释放了它。然后，该上下文使用相同的元组在相同的 slab 地址重新分配一个 SYN cookie 请求。然而，过时的查找引用了新对象并通过了元组重新检查；由于新请求缺少附加的监听器，TCP 接收路径尝试解引用一个空监听器，从而导致内核崩溃。这种崩溃不仅影响容器中的 Web 服务器，还会导致整个主机崩溃。  
  
第二种情况涉及回收已满的子套接字，这可能导致远程释放后使用。然而，这需要嵌套的竞态条件，因此如果没有专门的技术，很难触发。目前，公开报告仅记录了拒绝服务崩溃。Kim 和任何供应商均未表示存在远程代码执行的可能性。  
  
这些问题的发生时间因环境而异。在 QEMU/KVM 虚拟机中，由于 vCPU 抢占增加了竞争窗口，默认的 Nginx、Apache 和 SSH 服务器会在大约 5 秒到 2 分钟内崩溃。相反，在一台空闲的裸机 Nginx 服务器上（配备 8 个 RX 队列），经过精心调整时间的验证性测试 (PoC) 耗时约 14 小时才成功。  
  
该漏洞于 2015 年 10 月 3 日在提交 079096f103fa 中引入。修复程序（提交 4e2b3ef19e0e）于 2026 年 11 月 3 日合并。上游修复程序包含在 Linux 6.12.117、6.18.63 和 7.3.4 中。  
  
截至11月15日，许多发行版尚未发布已修补的内核。此问题与近期其他内核网络漏洞类似，例如CVE-2026-98432，该漏洞允许远程攻击者使Ubuntu系统崩溃。此外，它还与18年前的SCTP释放后使用漏洞遥相呼应，表明此类生命周期内的错误可以隐藏多久。  
  
首要任务是应用补丁。如果无法应用补丁，Kim 列出了两种临时缓解措施。第一种是使用 `sudo sysctl -w net.ipv4.tcp_syncookies=0` 关闭 SYN cookie。此设置应用于每个网络命名空间，因此每个拥有自己命名空间的容器都需要进行此设置，但这会削弱 SYN 洪水攻击的防护能力。第二种方法是将入站接口减少到单个接收队列，并禁用 RPS 和 RFS，这样就能阻止竞争条件。管理员还应该重启进入已打补丁的内核，并使用 `uname -r` 命令进行确认。这类 TCP 竞争条件并非新鲜事。
