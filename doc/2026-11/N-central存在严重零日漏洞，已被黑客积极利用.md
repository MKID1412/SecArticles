#  N-central存在严重零日漏洞，已被黑客积极利用  
原创 ZM
                    ZM  暗镜   2026-11-17 22:00  
  
N-able公司发出警告，在其远程监控和管理（RMM）平台关键漏洞的概念验证（PoC）代码发布后，攻击者正积极扫描存在漏洞的N-central服务器。该公司于2026年11月9日宣布发生重大服务中断事件，并注意到与已发布的PoC代码相关的扫描活动有所增加。  
  
N-able 发布了N-central 2026.4 Hotfix 2（版本 2026.4.1.26），并公布了七个 CVE 漏洞。这些漏洞包括 XML 外部实体 (XXE) 漏洞、OGNL 注入漏洞、存储型跨站脚本 (XSS) 问题、服务器端请求伪造 (SSRF) 问题以及两个本地权限提升路径。  
  
其中最严重的漏洞是 CVE-2026-125882，这是一个远程代码执行漏洞，由文件库上传函数中的路径遍历漏洞引起。Sprocket Security 的 Nate Fair 被认为是该漏洞的发现者。其他六个漏洞分别是：  
- CVE-2026-125883：多个 XXE 漏洞。  
- CVE-2026-125878：多个 OGNL 注入漏洞。对象图导航语言 (OGNL) 注入已导致其他 Java 产品中的远程代码执行。  
- CVE-2026-125879：通过可写的 syslog-ng 配置将本地权限提升到 root。  
- CVE-2026-125880：在管理员上下文中，通过 MMS3 补丁元数据存储 XSS 漏洞。  
- CVE-2026-125881：通过服务导入架构验证进行 SSRF 攻击。  
- CVE-2026-91000：通过不安全的进程间通信 (IPC) 通道进行本地权限提升。  
-able 还表示，后续的热修复程序将提供进一步的安全更新。  
  
RMM 服务器控制着许多下游端点，因此一旦遭到入侵，攻击者就能获得访问所有受管客户的途径。N-central 之前就曾遭受过攻击。攻击者利用CVE-2026-18577漏洞获取了管理员权限并滥用了“控制”功能。  
  
CISA后来将该漏洞添加到其“已知已利用漏洞”目录中。在这些攻击中，入侵者还注册了Cloudflare隧道服务以实现持久化。  
  
N-able 于 2026 年 11 月 11 日 01:04 UTC 确认，所有区域的所有托管 N-central (NCOD) 服务器均已升级。本地管理员必须自行升级。支持的直接升级路径包括 2025.4、2026.1、2026.2、2026.3、2026.3.1 Hotfix 1 至 4 以及 2026.4（包括 Hotfix 1）。早期版本必须先升级到受支持的版本。
