### 泛微 E-cology 10 DubboApi 调试接口未授权远程代码执行（CVE-2026-22679）  
  
**漏洞分析**  
  
/papi/esearch/data/devops/dubboApi/debug/method  
 这个本该只在开发环境存在的 Dubbo 调试端点，在 E-cology 10 的生产版本里默认保留，且没有任何认证。POST 请求的三个参数 interfaceName  
、methodName  
、params  
 全部由用户控制，底层通过 Dubbo 调用任意内置类与方法。系统里恰好有个 CommandExecHelper  
，封装了 Runtime.getRuntime().exec()  
，把 interfaceName  
 指向它、methodName  
 指向执行方法、params  
 填上命令，整条链就通了。CVSS 4.0 评分 9.3。3 月 12 日官方发补丁，3 月 17 日就被抓到来定向攻击，3 月 31 日 Shadowserver 确认进入在野利用阶段，4 月底开始批量扫描。攻击者不需要落地 Webshell，这个调试端点本身就是 shell——发什么就执行什么，然后把结果原样返回。  
  
**影响版本**  
  
E-cology 10.0，安全补丁版本低于 v20260312。  
  
**修复建议**  
  
升级到 v20260312 及以上，当前全量安全补丁为 v20260716。升级后实测该端点应返回 404 或 401，而不是 200。来不及升级的，先在 Nginx 给 /papi/  
 加 Basic Auth，WAF 侧对该路径做全局拦截。日志里重点排查 interfaceName=com.weaver  
 配合 methodName=execCommand  
 的 POST 请求。已经被打进去的，光删 Webshell 没用，数据库连接串、API 密钥、域账号哈希全部要轮换。  
  
**来源**  
  
泛微官方安全补丁下载中心；奇安信 CERT 风险通告；泛微官方安全通告 / 阿里云漏洞库

### 泛微 E-cology XML外部实体注入（XXE，2026年披露）  
  
**漏洞分析**

**影响版本**

应用官方补丁；在XML解析器中显式禁用 DOCTYPE 和外部实体；边界WAF对包含 SYSTEM、PUBLIC 等关键字的XML请求做检测拦截。

### 致远 OA designer.do 远程代码执行漏洞（2026年披露）  
  
**漏洞分析**  
  
漏洞根因是程序对用户上传的ZIP文件缺乏严格校验。远程攻击者向 designer.do 接口发送精心构造的ZIP文件，即可在服务器上执行任意命令。designer.do 是致远OA中较常暴露的接口，这条漏洞的利用路径清晰，在2026年的攻防演练中属于边界打点的高频候选。  
  
**影响版本**  
  
以官方受影响版本列表为准（2026-01-08 披露）。  
  
**修复建议**  
  
更新至官方修复版本；在WAF层对 designer.do 的上传请求做严格的文件类型与内容检测，禁止ZIP中包含可执行脚本或路径遍历序列。  
  
**来源**  
  
isecurity.huawei.com（致远OA designer.do RCE）

### 致远 OA JDBC 反序列化代码执行漏洞

### 通达OA OfficeTask 前台未授权RCE / SQL注入（UDP 2397）  
  
**漏洞分析**  
  
通达OA的定时任务服务 OfficeTask 开放 UDP 2397 端口，未授权即可接收数据，并根据数据中的命令控制字符串执行指定任务，导致未授权任意PHP文件执行和SQL注入。这条漏洞的特殊之处在于走UDP、不走HTTP，大部分基于HTTP流量检测的WAF和NDR容易漏掉。2026年的蓝队如果只盯80/443，几乎必然漏掉这一类入口。  
  
**影响版本**  
  
以官方通告为准（2025-05-28 分析披露）。  
  
**修复建议**  
  
在边界防火墙/安全组层默认封禁UDP 2397，仅允许明确可信的集群节点间通信；若业务必须开放，对UDP载荷做深度检测；升级通达OA至修复版本。  
  
**来源**  
  
FreeBuf（通达OA OfficeTask前台RCE、SQL注入分析）

### 通达OA PHP2Shell 相关内存破坏漏洞（CVE-2026-109618 / CVE-2026-109619）  
  
**漏洞分析**  
  
通达OA的Web服务运行在PHP之上，直接受PHP内核的“PHP2Shell”漏洞影响。未经身份验证的远程攻击者可通过发送特制multipart请求，在应用代码执行前触发内存破坏。这是运行时层漏洞，通达OA自身代码无法完全防御，蓝队需要把PHP运行时版本也纳入资产清点。  
  
**影响版本**  
  
受PHP内核 CVE-2026-109618 / CVE-2026-109619 影响的所有通达OA版本；CNVD编号 CNVD-2026-42444。  
  
**修复建议**  
  
优先升级PHP运行时至官方修复版本；若无法立即升级PHP，在边界WAF对multipart请求的畸形边界和超大/异常负载做检测拦截；同时关注通达OA官方发布的适配补丁。  
  
**来源**  
  
CNVD-2026-42444 / 通达OA V13.7发布公告  
### 通达OA 任意文件上传绕过 + UDF 提权RCE（实战链）  
  
**漏洞分析**  
  
2026年的公开案例显示，通达OA的任意文件上传防护可以被绕过，配合MySQL UDF提权可完成从Web入口到系统命令执行的完整链路。这不是单一CVE，而是一条组合利用链，意味着即使单点漏洞被打了补丁，攻击者仍可能通过上传绕过 + 数据库提权打通。蓝队排查时不能只盯单个CVE，要检查上传点、数据库权限和 plugin_dir 的可写性。  
  
**影响版本**  
  
以实际存在上传绕过和UDF提权条件的通达OA版本为准。  
  
**修复建议**  
  
升级上传组件的校验逻辑，禁止仅依赖前端或Content-Type判断；收紧数据库账户权限，禁用 FILE 权限和 CREATE FUNCTION；对 plugin_dir 目录实施只读或严格ACL。  
  
**来源**  
  
cn-sec.com / wx.secv.cc（通达OA任意文件上传绕过+UDF绕过RCE案例）

### Exchange Server MRSProxy 预认证 NTLM 中继 RCE（CVE-2026-62911）  
  
**漏洞分析**  
  
这是2026年Exchange最需要盯的一条。MRSProxy 的WCF端点由 HTTP.sys 承载，但缺少Extended Protection for Authentication（EPA） ，攻击者可以通过NTLM中继到该端点，实现预认证远程代码执行，最终以SYSTEM权限落地Webshell。更关键的是，在Pwn2Own上演示后，公开PoC已经出现，约有 21,000台 Exchange Server暴露在风险中。蓝队如果只查补丁不看EPA配置，等于没有查。

### Tomcat 部分PUT + FileStore会话反序列化链RCE（CVE-2025-24813）  
  
**漏洞分析**  
  
这条漏洞的利用需要多个条件同时满足：DefaultServlet的写入被启用、支持部分PUT、应用使用基于文件的会话持久化并位于默认存储位置、且类路径中存在可用于反序列化的库。但在满足条件的Spring Boot + Tomcat部署中，它可以形成从部分PUT写入到会话反序列化的完整RCE链。蓝队排查时不要因为“条件多”就跳过，先确认DefaultServlet的 readonly 参数和会话持久化配置。  
  
**影响版本**

Jenkins 用 Remoting 库在控制器与 agent 之间通信，通过序列化 Java 对象传递。控制器端的反序列化逻辑存在缺陷，具备相应权限的用户可远程执行代码。CI 服务器上通常挂着全部源码、构建凭据和发布令牌，是供应链上的关键一跳。换个角度看同一条：具备 Agent/Connect 权限的攻击者可以绕过 JEP-200 反序列化过滤器，直接加载 Java 对象。  
  
**影响版本**  
  
Jenkins 2.575 及更早版本、LTS 2.568.1 及更早版本，2026 年 8 月发布的官方公告中列为严重级别，修复版本为 Jenkins 2.576 与 LTS 2.568.2。  
  
**修复建议**  
  
升级到 Jenkins 2.576 与 LTS 2.568.2 及以上版本；控制器与 agent 通信端口必须做来源限制，不要暴露在办公网。  
  
**来源**  
  
Jenkins 官方安全公告；VulDB（CVE-2026-70426）

**来源**

## 七、堡垒机  
  
**JumpServer**  
### JumpServer Applet Host 部署 Jinja2 模板注入（CVE-2026-44845）  
  
**漏洞分析**  
  
拥有 Applet Host 管理与部署权限的管理员，可以在 IP 或 Host 字段、Core Service Address 字段注入 Jinja2 表达式。部署时 Ansible 会求值 ansible_host  
 库存数据与 playbook 变量，表达式随之落地执行任意命令。  
  
**影响版本**  
  
JumpServer 4.10.17 之前版本，修复提交为 cc57ba0。  
  
**修复建议**  
  
升级到 4.10.17 及以上；堡垒机里的模板字段本身就要当作高危注入点来审，配置项也要纳入权限分离。  
  
**来源**  
  
GitHub 安全公告；VulDB（CVE-2026-44845）  
### JumpServer 模板渲染命令注入（CVE-2026-112159）  
  
**漏洞分析**  
  
模板渲染组件的 IP 与 HOST 参数存在操作系统命令注入，利用方式已公开。堡垒机是全公司资产的钥匙，这一处失守等于所有纳管主机同时失守。  
  
**影响版本**  
  
JumpServer 4.10.19 及之前版本，升级到 5.0.0 可修复。  
  
**修复建议**  
  
升级到 5.0.0；同时确认堡垒机自身没有暴露在公网，控制台登录地址建议加白名单限制。  
  
**来源**  
  
漏洞详情  
### JumpServer Chen组件 fastjson 反序列化RCE（CVE-2026-16723，在野利用）  
  
⚠️ 已在野利用  
  
**漏洞分析**  
  
这是2026年堡垒机领域最需要立即处置的一条。JumpServer 的 Chen 组件依赖的 fastjson 存在反序列化漏洞，2026年9月的安全态势报告已经观测到针对公网暴露JumpServer的在野RCE攻击，且攻击量级上升。堡垒机是“集权系统”中的集权系统，一旦被打穿，攻击者可以直接控制其纳管的所有机器。这条漏洞的优先级应该高于绝大多数OA和中间件漏洞。  
  
**影响版本**  
  
JumpServer Chen组件受影响的fastjson版本；具体以JumpServer官方安全公告为准（CVE-2026-16723）。  
  
**修复建议**  
  
立即升级JumpServer至修复版本；在无法立即升级的窗口期，禁止JumpServer控制台直接暴露于互联网，通过VPN/零信任网关访问，并设置源IP白名单；在边界WAF/NDR层启用fastjson反序列化攻击检测规则；排查JumpServer日志中是否存在异常的Chen组件请求。  
  
**来源**  
  
JumpServer Security Advisories / 阿里云安全态势报告（CVE-2026-16723）  
### JumpServer YAML配置处理SSTI/RCE（CVE-2026-31864）  
  
**漏洞分析**  
  
该漏洞存在于JumpServer的YAML配置文件处理逻辑中，可导致SSTI/RCE，命令在JumpServer Core容器内执行。根据代码演进分析，从2023年4月i18n功能引入时该缺陷就已存在，直到2026年2月才修复。这意味着大量运行旧版本JumpServer的部署可能在长达近三年的时间里处于风险中。蓝队不能只看“最近有没有升级”，要核对具体的修复版本边界。  
  
**影响版本**  
  
JumpServer 修复版本之前的多个版本（缺陷自2023年4月引入，2026年2月修复）。  
  
**修复建议**  
  
升级至包含该修复的JumpServer版本；审查YAML配置的渲染流程，禁止在模板中执行用户可控表达式；限制能够上传/修改远程应用YAML配置的角色。  
  
**来源**  
  
奇安信攻防社区（CVE-2026-31864）  
### JumpServer KoKo SFTP路径遍历（CVE-2026-54336）  
  
**漏洞分析**  
  
KoKo Web Terminal 的SFTP功能存在路径遍历，攻击者可利用该缺陷突破预期的文件访问边界。堡垒机的SFTP通道直连纳管主机，路径遍历可能将受限的文件访问扩展为对更广泛路径的读写，在横向场景中价值很高。  
  
**影响版本**  
  
以JumpServer官方安全公告为准（CVE-2026-54336）。  
  
**修复建议**  
  
升级至修复版本；在KoKo层对SFTP路径做规范化校验，拒绝包含 .. 或绝对路径的请求；限制SFTP可访问的根目录范围。  
  
**来源**  
  
JumpServer Security Advisories（CVE-2026-54336）

## 八、2026年新增重点暴露面（AI工具栈、云原生与供应链）  
### AI工具与自动化平台正在成为红队的“新边界”  
  
2026年的攻防演练中，攻击队已经将ComfyUI、Crawl4AI、Langflow、n8n等AI工具和自动化平台纳入重点扫描范围。这些平台往往由业务团队自行部署，不在传统安全团队的资产清单里，默认配置暴露、未授权访问、依赖组件漏洞的比例很高。蓝队需要立即做一件事：把内部AI工具栈当成正式资产来盘，而不是等红队扫描出来再补。  
  
排查建议：清点上述平台的版本与网络暴露面；禁止管理界面和API默认暴露于互联网；对MCP Server类组件（如mcp-atlassian）同样纳入资产台账和SSRF排查范围。  
### 云原生与供应链侧风险  
  
2026年攻防演练明确将K8s容器逃逸、云权限越权列为高频考点，同时也是蓝队失分较多的区域。同时，中间件与基础组件的供应链漏洞（如Tomcat Tribes回归、Java4Shell影响Jenkins/Jira/Keycloak等）说明一个问题：不能只盯“应用层CVE”，运行时和基础组件的版本同样是攻击面。  
  
排查建议：对Apache、F5、东方通等中间件以及JDK运行时进行版本地毯式排查，尤其关注五年以上未升级的老系统；检查K8s RBAC、ServiceAccount权限和容器 securityContext 配置，优先收敛 cluster-admin 和 hostPath 挂载；将CI/CD工具链（Jenkins、GitLab Runner）纳入边界防护和凭据轮换范围。

## 结语：这份清单怎么用  
  
按本文列出的条目对着资产清单过一遍，优先级这样排：  
1. **先看在野利用条目**  
。CISA 在野利用目录里出现过的，说明已经有攻击者在用，不需要犹豫，直接排期升级。  
  
1. **再看是否暴露公网**  
。同样一个漏洞，挂在公网和挂在内网，处理顺序完全不同。  
  
1. **最后看补丁窗口期**  
。泛微那条补丁发出去第 5 天就被打穿了，评估期超过一周基本等于放弃。  
  
三条通用原则：开发调试类接口在生产环境必须默认关闭，不要指望补丁能覆盖没开的门；管理面全部收进内网专线；任何补丁打完都要实测验证一遍，看漏洞端点是不是真的返回 404。  
  
漏洞清单会过期，这份清单也一样。建议按季度回查一次，尤其是 CISA 目录——它的更新频率比厂商公告还快。
