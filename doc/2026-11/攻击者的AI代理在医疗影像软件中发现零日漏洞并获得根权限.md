黑客利用AI智能体，在开源医学影像服务器MONAI Label中发现了一个此前未知的漏洞，并获得了某大学服务器的  
ROOT  
访问权限。  
  
![](https://mmbiz.qpic.cn/mmbiz_png/PaFY6wibdwyL3quHlSztYe6vsu9PCUyDZRvYq8icVkiaMIeryFN0QeEQtibIyKtJ2V4n82Wyctsl3TVfiaxDRxQIiafJVicMNVy6rAzXhlBjz5qaqU/640?wx_fmt=png&from=appmsg "")  
  
  
该漏洞允许无账号的攻击者在服务器存储文件夹外写入文件，且在默认未启用登录的设置下，MONAI Label 0.8.5及更早版本均受此影响。  
  
  
维护者已在源代码中合并了修复程序，但目前仍没有可安装的修复版本。  
  
  
MONAI Label 是研究团队用于标注医学扫描图像和训练影像模型的服务器，它与更广泛的 MONAI 框架是相互独立的程序。  
  
  
该漏洞是服务器存储上传图片和标签的模块中存在的目录穿越缺陷。调用方提供的文件标识符会被追加到存储文件夹后直接写入磁盘，且未检查生成的路径是否仍在该文件夹范围内。  
  
  
服务器以其运行账户的权限进行写入，因此攻击者无法在计算机的任意位置写入，但可写入的代码或配置文件位置会为运行代码开辟途径。默认情况下身份验证处于关闭状态，因此任何能通过网络访问该服务器的客户端都能触发写入操作。0.8.5 及更早版本受此影响。  
  
  
亚马逊在发现操作员自己的Cairn控制面板未设密码暴露在互联网上后，对此次入侵事件进行了重建调查。Cairn 是一个开源框架，可将 AI 智能体作为自动化渗透测试工具运行，而暴露的控制面板泄露了这些智能体的任务设置、提示词以及运行历史。  
  
  
该公司在其事件报告中表示，在9月大约48小时的时间里，这些智能体完成了应用程序界面的映射，并在约11分钟内完成了向服务器写入文件的操作。  
  
  
这些智能体几乎无需按步骤接受指导。据该公司称，操作员设定了获取 shell 访问权限的目标并选定了目标，而具体的方法则由智能体自行选择。  
  
  
攻击者获得了 root 权限的 shell，但并非在那 11 分钟之内。在另一个会话中，攻击者利用同一个漏洞植入了一个 Python 启动时会自动运行的文件。接着触发了一个训练功能，该功能启动了一个新的 Python 进程，这个进程加载了该文件，并以 root 身份反向连接到攻击者的设备。  
  
  
该根访问权限仅针对一台大学服务器，而另一台 MONAI Label 系统是否会得到相同结果，取决于其运行方式以及服务账户的权限范围。  
  
  
在随后的一次会议中，运维人员向这些智能体提供了一个隧道，用于接入另一所运行相同软件的大学网络。亚马逊认为该网络也是以同样方式被入侵的，但尚未确认这起二次入侵事件。  
  
  
维护人员确认了该漏洞，并于10月19日合并了源代码修复，该修复强制上传操作在已批准的文件夹内完成，并拒绝空名称或以点开头的名称。  
  
  
他们本周早些时候发布的安全公告仍未列出已修复版本，并表示该修正将在未来版本中推出。最新的版本列表仍为 2024 年的 0.8.5 版本。源代码中已合并的修复程序与可安装的软件包并非同一概念。  
  
  
该漏洞现已被列入CVE 记录，编号为 CVE-2026-133968，于本周发布，评分高达 10 分制中的 9.8 分，属于严重等级。该项目的公告中仍未显示分配到任何 CVE 编号，这只是该页面更新存在延迟，并非存在第二个漏洞的迹象。
