#  Ruby 中一个严重的单字节堆溢出漏洞可能导致远程代码执行攻击  
原创 ZM
                    ZM  暗镜   2026-11-23 22:00  
  
Ruby 已修复一个严重的内存损坏漏洞，该漏洞可能允许攻击者在易受攻击的服务器上执行远程代码 (RCE)。该漏洞被 Veria Labs 追踪，编号为 GHSA-34m4-m9fh-gqp5，并被命名为 ruby2ßhell，它影响 Ruby 的字符串大小写转换代码。  
  
研究人员报告称，攻击者无需登录运行 Ruby on Rails或采用默认设置的经典 Sinatra 应用程序，即可通过网络访问存在漏洞的代码。披露时，该漏洞的 CVE 编号仍在申请中。  
  
该缺陷出现在几种旧式单字节编码的大小写转换例程中，包括一些 ISO-8859 和 Windows-125x 变体。在这些编码中，Ruby 在将德语小写字母 ß 转换为大写时，会将其转换为 SS。这种转换会从一个输入字节产生两个输出字节，但循环只会检查输出缓冲区是否还有空间容纳下一个字节。如果转换需要两个字节，而缓冲区只容纳一个字节，则第二次写入操作会超出缓冲区边界。  
  
这是堆缓冲区溢出，因为输出缓冲区位于运行时分配的内存中。转换后的字符串的后续副本也可以读取缓冲区之外的一个字节。  
  
受影响的代码可以追溯到 Ruby 2.4.0 版本，可通过 upcase、swapcase、downcase(:fold) 和 casecmp? 函数访问。UTF-8 字符串遵循独立的代码路径，不会触发此漏洞。  
  
Ruby 的维护者表示，概念验证漏洞利用已经证明在某些情况下可以执行代码，但这并不意味着每次越界写入都会导致远程代码执行 (RCE)。  
  
受影响的版本包括 Ruby 3.3.0 至 3.3.13、3.4.0 至 3.4.12 以及 4.0.0 至 4.0.9。该漏洞也影响更早的版本，包括 Ruby 2.4.0。Ruby 3.2 及更早版本已停止维护，并且没有针对此问题的修复程序。  
  
根据 Veria Labs 的说法，Plain Rack 默认情况下不会暴露。但是，如果自定义应用程序代码对旧版编码中不受信任的文本应用受影响的大小写转换，则仍然可能引入风险。  
  
Veria Labs 确定受影响的 Ruby 运行时与 GitLab 19.6.0、GitHub Enterprise Server 3.22.5、Mastodon 4.7.5、OpenProject 17.9.7、Discourse 2026.10.1 和 Chatwoot 4.20.0 捆绑在一起。  
  
对于管理员而言，关键细节在于应用程序实际加载的是哪个 Ruby 运行时环境。更新主机系统自带的 Ruby 并不会替换应用程序包、设备或容器镜像中包含的独立运行时环境。  
  
Ruby 团队于 2026 年 11 月 18 日发布了 3.3.14、3.4.13 和 4.0.10 版本。官方的 Ruby 安全版本修复了字符串大小写转换和正则表达式引擎中的七个缺陷。  
  
这些漏洞与之前编号为 CVE-2026-97229 的 GitLab CI/CD 正则表达式漏洞无关，网络安全新闻 (Cyber Security News) 也曾报道过该漏洞，当时 CISA 警告称该漏洞已被积极利用。之前的漏洞利用并不能证明 ruby2ßhell 已被实际利用。  
  
自行管理 Ruby 运行时的团队，如果运行的是 Ruby 3.2 或更早版本，则应升级到其分支的修复版本或迁移到受支持的分支。  
  
自托管产品的管理员应安装供应商提供的修复版本，然后在运行的应用程序环境中验证 Ruby 版本。优先考虑面向互联网的部署，因为这些部署中的漏洞代码无需身份验证即可访问。
