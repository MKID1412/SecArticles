#  Mongoose 堆溢出远程代码执行漏洞已在 7.24 中修复  
sec随谈
                    sec随谈  sec随谈   2026-11-23 01:21  
  
Cesanta 已发布 Mongoose 7.24，修复其嵌入式网络库中的七个漏洞。其中最严重的是一个评分为 CVSS 9.8 的 Mongoose 堆溢出漏洞，可能在无需身份验证的情况下实现远程代码执行。该漏洞由趋势科技的零日计划（ZDI）报告。  
  
**摘要**  
  
这些漏洞影响 Mongoose 内置的 TCP/IP 协议栈、TLS 协议栈和 WebSocket 解析器。其中两个被评为严重，大多数无需登录。有几份公告包含概念验证材料，但尚未确认存在在野利用。  
  
**重要性**  
  
**嵌入式设备很难打补丁**  
  
Mongoose 运行在工业和物联网设备的固件中。据研究人员   
Simone Margaritelli（evilsocket）  
称，Cesanta 声称其部署在数亿台设备上。这个数字是厂商自己的估计。无论如何，每个设备制造商都必须重新构建并发布新固件，这往往需要数月时间。  
  
**无需登录，也无需协议**  
  
Mongoose 是一个流行的嵌入式 Web 服务器和网络库。这使得新发现的 Mongoose 堆溢出漏洞尤其严重。它在 TCP 层触发，早于任何 HTTP、MQTT、TLS 或 WebSocket 解析开始之前。换句话说，应用的登录页面起不到任何保护作用。  
  
**今年的第二波**  
  
这不是 2026 年第一批 Mongoose 漏洞。4 月，Mongoose 7.21 修复了   
CVE-2026-5244  
 和   
CVE-2026-5245  
，两者都是未认证的远程代码执行漏洞。现在，  
Mongoose 安全公告  
又增加了七个影响 7.23 及更早版本的问题。  
  
**攻击原理**  
  
**MIP 中的 Mongoose 堆溢出（CVSS 9.8）**  
  
ZDI 在 read_conn() 中发现了该漏洞，它是 MIP 内置 TCP/IP 协议栈的一部分。携带数据的 TCP FIN 数据包会跳过缓冲区大小调整检查。结果，数据被复制到堆缓冲区末尾之外。  
  
公告称其为实现任意代码执行的教科书式堆溢出原语。公告还补充说，该漏洞无需认证、早于任何协议处理，只需要能够访问任何开放的 TCP 端口。MIP 还面向缺少 ASLR 和栈金丝雀的微控制器。  
  
**WebSocket 帧注入（CVSS 9.3）**  
  
在 32 位平台上，WebSocket 解析器会截断 64 位的负载长度。精心构造的长度可能回绕为零，使后续字节变成新的帧。公告警告称，这使得"认证前消息注入"成为可能，并且在控制仪表板上，无需任何登录即可获得完全控制。ESP32、STM32 和 RP2040 开发板运行的都是 32 位代码。  
  
**TLS 和网络解析漏洞**  
- 证书时间戳（7.5）：月份值为零，会在 TLS 握手期间导致越界读取。  
  
- ECDSA 签名解析（7.5）：证书签名中超大的长度值会使进程崩溃。  
  
- ClientHello 扩展（高危）：被截断的扩展块会导致堆越界读取。  
  
- IPv6 校验和（7.5）：带有扩展头的精心构造 IPv6 数据包会导致越界读取。  
  
- IP SAN 检查（7.4）：如果 Subject CN 匹配，TLS 客户端可能会接受针对错误 IP 地址的证书。  
  
其中大多数会使设备崩溃。不过，有些在 32 位系统上可能泄露内存。  
  
**受影响版本**  
- Mongoose 7.23 及更早版本  
  
- IP SAN 绕过影响 7.19 至 7.23  
  
暴露情况取决于构建选项。例如，MIP 和 IPv6 漏洞需要内置的 TCP/IP 协议栈。同样，TLS 漏洞需要内置的 TLS 后端 MG_TLS_BUILTIN。  
  
**补丁与缓解措施**  
  
请升级到 Mongoose 7.24 并重新构建您的固件。公告中没有列出任何变通方案，目前也尚未分配 CVE 编号。  
  
**设备制造商的操作步骤**  
- 检查您的产品使用了哪个 Mongoose 版本和哪些构建标志。  
  
- 为暴露 MIP、WebSocket 或 TLS 服务的设备发布固件更新。  
  
- 限制对嵌入式管理界面的网络访问。  
  
**设备所有者的操作步骤**  
  
请询问厂商其产品是否嵌入了 Mongoose。与此同时，请让物联网和工业设备远离开放的互联网。最后，请在厂商发布固件更新后立即应用，因为每一个 Mongoose 堆溢出的修复都依赖于那次重新构建。
