一个支付字段，不用登录，就能把一段 PHP 代码拼进模板里执行。s2Member 两个月内已经在同一个地方栽了第二次，上一次堵的是另一个字段。  
  
## 01  事情是什么  
  
11 月 2 日公开的 CVE-2026-86596，CVSS 9.8，归类是代码注入（CWE-94）。  
  
s2Member 是给 WordPress 做会员制、付费墙、订阅收款的插件。装它的站基本都在卖东西：卖课、卖社群、卖资料下载、卖会员内容。版本号用日期制，260927 就是 2026 年 9 月 27 日那一版，凡是不高于它的都算受影响。  
  
出问题的地方不是登录、不是权限判断，是 PayPal 通知邮件的模板填充。攻击者往   
item_name  
 这个支付字段里塞东西，插件把它拼进邮件模板时，会拼出一段能执行的 PHP。  
  
## 02  为什么危险  
  
先看插件自己的防护。它在拼模板之前，会把支付数据整体过一遍 strip_php_tags_deep()：  
  
// utils-strings.inc.php L201  
  
$copy = html_entity_decode($copy);  
  
$copy = rawurldecode($copy);  
  
// 实体与 URL 编码解码三遍  
  
while (strpos($copy,'<?')!==false)  
  
  $copy = str_replace('<?',  
  
    'NEUTERED_', $copy);  
  
思路很清楚：把实体编码、URL 编码都拆开，最后干掉字面量 <?。单个字段里只要没有这两个字符，这一层就当你干净。  
  
问题是这层过滤只做一次，而模板填充是级联的。每个字段依次替换，前一步插进去的值，还会被后面的替换再扫一遍：  
  
$msg = preg_replace(  
  
  '/%%item_name%%/i',  
  
  $paypal['item_name'], $msg);  
  
$msg = preg_replace(  
  
  '/%%first_name%%/i',  
  
  $paypal['first_name'], $msg);  
  
// 清掉没匹配上的占位符  
  
$msg = preg_replace(  
  
  '/%%(.+?)%%/i', '', $msg);  
  
于是 < 和 ?php 可以分头进来：item_name 填 <%%first_name%%，first_name 填 ?php 开头的一段代码。  
  
单独看，两个字段都没有 <?，过滤层放行。item_name 先被插进模板，串里留下 <%%first_name%%；紧接着 first_name 那一步替换，把它拼成完整的 PHP 起手标签。最后那行清占位符的正则只删 %%，不管 PHP 标签。  
  
链路的终点在 utilities.inc.php 第 49 行，插件自己的模板求值函数：  
  
public static function evl($code) {  
  
  ob_start();  
  
  eval('?>'.trim($code));  
  
  return ob_get_clean();  
  
}  
  
模板内容在这里被当成 PHP 求值。所以这不是往邮件里塞一段文本，是往 eval 里塞代码，也解释了为什么定级是代码注入而不是 XSS。  
  
需要说清一点：官方描述里还留着一句需要 custom-level 权限，但标题和 CVSS 向量（PR:N、AC:L、UI:N）都按无认证算。两处矛盾，按最坏的算，当无认证处理。上面这条拼接路径是顺着代码推的，官方没放 PoC，我也没有在真实站点上验证过，别拿它去打不属于你的站。  
  
## 03  这不是第一次  
  
8 月底那一版也出过同类型的洞：CVE-2026-19804，CVSS 8.8，无认证，位置是回跳代理里的 first_name 参数，9 月 24 日公开。当时的修法就是加前置过滤，也就是上面那段 strip_php_tags_deep。  
  
两个月后，同一个回跳入口、同一条邮件模板管线，换个字段又通了一次。按字段打补丁，管线本身没动，这种修法撑不了多久。这一点比单个 CVE 更值得记。  
  
## 04  谁受影响  
  
·  
 WordPress 站点装了 s2Member，版本 ≤ 260927  
  
·  
 站点启用 PayPal 收款或 PayPal 回跳代理（会员收款最主流的方式之一）  
  
·  
 上面这些代码在免费版框架里，不必装 Pro  
  
·  
 WordPress.org 统计当前约 8,000 个站点在跑这个插件  
  
8 千不算多。但 s2Member 的定位决定了这批站的质量不低：凡是用它的，基本都有真实付费用户、订单流水和会员资料，拿下就是一笔现成的数据。  
  
打这类站的成本也很低。插件目录下的 readme.txt 直接写着版本号，/wp-content/plugins/s2member/ 这个路径本身就是指纹，随便哪个空间测绘平台搜一下，就能把版本落在受影响区间的站排出来。会员站还有个特点：为了卖东西，注册页和收款页必然是开放的，攻击面比普通企业站大一圈。  
  
## 05  怎么修  
  
1. 后台插件页看版本，≤ 260927 的升到 261001 以上，现在最新是 261017  
  
2. WP-CLI 一行确认：  
wp plugin list --name=s2member  
  
3. 一时升不了：停掉 PayPal 回跳，或暂停 Pro-Form 收款邮件，等能升级再打开  
  
4. 加一条 WAF 规则，拦 item_name 里出现 <? 或 %% 的请求  
  
5. 查有没有被打过：访问日志里搜 s2member_paypal_proxy 的 POST，重点看 item_name 字段内容；再看 uploads 目录近期有没有陌生的 php 文件  
  
## 06  一句判断  
  
无认证、可直接 eval、影响面 8 千个带支付能力的站，三个条件凑齐，没什么好犹豫的，今晚就升。AC:L 加 PR:N 意味着门槛低到脚本就能扫，这种洞进野外武器库只是时间问题。  
  
从红队角度看，这个洞的价值在于省掉了拿账号那一步：不用先注册，不用先付一次会员费，一条 POST 就到了 eval。反过来看防守，只盯着 XSS 和文件上传的检查清单，最容易漏掉模板求值这条老路。
