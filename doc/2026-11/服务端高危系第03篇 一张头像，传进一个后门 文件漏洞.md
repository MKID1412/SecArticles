一个新业务上线前，例行检查「头像上传」：传 jpg 正常，改后缀 .php 被拦，把 Content-Type 改成 image/jpeg 也被拦，最后传了一张尾部带代码的「图片」——GIF89a 开头，服务端只认了文件头，原样存进上传目录，而那个目录是能执行脚本的。上线检查停了，这一版不许发。  
  
校验链每一层都没做错，错在最后一层：文件落盘的目录会执行脚本。前面拦得再多，漏过一个就等于全漏——判定不在请求里，在存储目录的权限里。  
  
**本文所有示例仅用于授权测试环境与防守规则验证，请勿用于未授权系统。上传类演示仅针对自有测试账号。**  
  
CHAPTER 01  
  
攻击原理：校验逐层可骗，目录一执行就全盘皆输  
  
先看这条校验链是怎么被逐层探出来的，原理全在这几行里：  
  
# 头像上传校验链探测：每一层都在被问一次  
  
✅ 传 avatar.jpg          # 正常落盘，顺手拿到回显路径  
  
❌ 改后缀 avatar.php      # 被拦，后缀校验在位  
  
❌ Content-Type 造 image/jpeg  # 仍拦，后端不止看 MIME  
  
❌ 文件头 GIF89a + 尾部带代码  # 过检落盘——只认了文件头  
  
关键在最后两行。第三层「文件头」守的是格式不是内容——GIF89a 六个字节放在最前面，检查函数看到一张合法动图，看不到尾部还跟着一段 PHP 代码。落盘之后能不能执行，只剩一个变量：目录配没配解析。  
  
它不止一种打法。知识库按「骗哪一层」分了几类：

门槛最低、出手最多的一类是黑名单遗漏，先于一切花活：  
  
# 后缀变体清单：拦得住 php，拦不住全家  
  
❌ shell.php.jpg       # 双扩展名，只检查最后一个后缀就放行  
  
❌ shell.php%00.jpg    # 空字节截断（PHP<5.3.4），%00 后被丢弃  
  
❌ shell.php::$DATA    # Windows NTFS 数据流，存盘变回 shell.php  
  
❌ shell.PhP / .php5 / .phtml / .phar   # 大小写混淆与黑名单遗漏变体  
  
知识库把利用过程拆成六步，按序排下来就是一条完整的利用链：  
  
# 一条完整的文件上传利用链（与配图六步逐条对应）  
  
① 摸清上传校验链   # 前端/后缀/MIME/文件头逐层探测，确认检查点在哪几层  
  
② 绕后缀校验       # 双扩展、大小写、%00 截断、::$DATA、php5/phtml/phar 变体  
  
③ 绕 MIME 与文件头 # Content-Type 伪造成 image/jpeg，GIF89a 魔数打头  
  
④ 解析漏洞配合     # /uploads/shell.jpg/.php、Apache 多扩展向左解析、.htaccess 覆盖  
  
⑤ 落地执行         # 上传目录可执行，文件被访问一次即触发  
  
⑥ 持久化           # 从单次上传到反复落地留壳，一处后门变成多处

这六行里最值得记住的是 ③ 和 ④。③ 是本篇焦点：文件头校验只读开头几个字节，读得到 GIF89a，读不到后面跟着的东西。④ 更安静：文件名是合法的 .jpg，执行却发生在解析里，Nginx 把 /uploads/shell.jpg/.php 交给 PHP-CGI，Apache 多扩展向左解析到 php，图片从此被当脚本跑。配合 .htaccess 覆盖，连后缀都不用改：  
  
$ printf "GIF89a" > avatar.gif   # 文件头合法，尾部追加一段 PHP 代码  
  
$ curl -F "file=@avatar.gif;type=image/gif" https://demo.test/upload  
  
$ curl https://demo.test/uploads/avatar.gif/.php   # Nginx 解析漏洞触发执行  
  
# .htaccess 覆盖（Apache，AllowOverride 未关即生效）：  
  
AddType application/x-httpd-php .jpg  
  
名字是图片，文件头是图片，被访问的时候是脚本。传上去的从来不是一张头像，是一个后门。  
  
CHAPTER 02  
  
防守怎么检测：白名单 + 隔离 + 禁执行  
  
防守分三层：代码层根治、流量层监测、研判层分级，缺一层都会漏。  
  
代码层根治就一句话：**上传目录不执行脚本，非白名单文件不落盘。**  
   
知识库「防御措施」段的根治方向，配六件套用：  
  
# 代码层根治：白名单 + 魔数 + 重命名 + 隔离（六件套）  
  
白名单 : 后缀只认 jpg/png/gif，不靠黑名单   # 变体再多也进不来  
  
魔数   : 文件头校验 GIF89a/JPEG/PNG 签名    # 改后缀改 MIME 都骗不过  
  
改名   : UUID 重命名，原文件名不落盘        # 拼路径、截断全失效  
  
禁执行 : 上传目录 location 禁脚本解析       # 落了盘也执行不了  
  
分域   : 文件走独立存储域名，与 Web 根隔离  # 解析漏洞无脚本可解  
  
渲染   : 图片二次渲染后再入库              # 尾部藏的代码被洗掉  
  
审计按控制缺口狩猎的思路走：白盒检查上传处理函数，后缀判断是不是白名单、落盘前有没有文件头校验和重命名、存储目录配置里解析是不是关的；黑盒在自有测试环境传一张尾部带无害标记串的图片，看能不能原样取回。命中的进整改清单。

图注：三层防守——代码层白名单+隔离+禁执行、流量层频次与异常告警、研判层落盘对账，代码层唯一根治  
  
流量层要换个思路。伪造型上传的请求头和正常上传一模一样，按关键字拦不住——监测对象换成「频次、矛盾、落盘前」：  
  
# 上传接口监测基线：频次特征 + 矛盾特征（不是关键字）  
  
频次 : 同 IP 高频上传、失败重试节奏异常、深夜批量传图  
  
矛盾 : MIME 与扩展名不符、Magic Bytes 与声明格式不匹配，直接告警  
  
阻断 : 命中规则在落盘前掐断，请求不过、文件不落  
  
动手分先后：规则级阻断命中异常特征就做，源头级等研判确认，区别还是误伤面：  
  
# 发现即阻断：两级规则 + 本系关键点（命中即做）  
  
① 规则级: 上传接口加临时规则拦异常后缀与 Magic Bytes 不匹配  # Nginx location 立即禁 PHP 解析热修，可回滚  
  
② 源头级: 封 IP                    # 研判确认后执行，防误伤正常用户  
  
③ 关键点: 毒文件已落盘，按文件名+目录+创建时间清点删除，立即收回上传目录执行权限  # 只删规则拦不住下一次  
  
第 ③ 步是文件漏洞区别于注入系的关键：注入的毒在流量里，拦掉请求就干净；上传的毒已经落盘——规则只能拦下一次上传，带毒文件还在目录里，谁访问谁触发。必须两件一起做：清点删除带毒文件，收回上传目录执行权限。不清理落盘文件，删了规则还会再触发。  
  
研判层三看：看上传目录新增文件，计划外后缀、双扩展、刚传完就被访问即升级；看上传后的访问记录，上传与首次访问时间贴得极近的是重点；看解析日志，非脚本目录出现 PHP 执行记录就是实锤。单个可疑文件隔离观察，确认可执行或已触发，立即转应急。  
  
CHAPTER 03  
  
出事怎么应急：先收回权限，再清带毒文件  
  
确认文件上传落地，按「止血—取证—排查—上报」四步走。最容易犯的错，是只删了文件，忘了目录权限没动——下一个随时再进来。  
  
止血：立即收回上传目录的脚本执行权限（Nginx location 禁解析热修、Apache 移除 handler），按清单删除带毒文件。**上传请求原貌、落盘文件清单、访问日志别删，它们是证据。**  
  
取证：按证据纪律留两段东西——可复现的上传请求原貌，和可观察的落盘副作用。拉上传日志与访问日志做对账表，确认哪些文件带毒、哪些被访问执行过。  
  
排查：评估损失面。回溯带毒文件的访问与执行记录，确认触发时间和来源 IP；核查同目录同期上传的其他文件——同一套上传代码往往不止一个入口。  
  
上报与加固：白名单 + 文件头校验 + UUID 重命名 + 存储隔离 + 目录禁执行逐项落地。涉及服务器被控与数据泄露的，按《网络安全法》《个人信息保护法》和等保要求走上报流程。**护网期间发现的，第一时间报指挥部。**  
  
🛡️ 应急 Checklist（出事照着打勾）  
  
□ 上传目录执行权限已收回，带毒文件已按「文件名+目录+创建时间」清单删除  
  
□ 上传请求样本、落盘文件清单、访问日志已留存未删除  
  
□ 带毒文件的访问与执行记录已回溯，横向影响已排查  
  
□ 白名单校验、UUID 重命名、存储隔离与目录禁执行已加固  
  
□ 合规上报已完成（护网期间第一时间报指挥部）

CHAPTER 04  
  
写在最后  
  
文件上传漏洞不是新漏洞，它是「校验看名字和格式、目录却在执行」里埋着的雷。错的是把执行权限留在了存储目录。白名单、魔数校验、UUID 重命名、目录禁执行补齐了，双扩展、文件头伪造、解析配合这条链基本失效；没做，后缀拦得再全，也挡不住一张 GIF89a 开头的图片。  
  
今天回去干一件具体的事：把上传目录的 Nginx/Apache 配置翻出来，确认两件事——location 对脚本解析是不是 deny 状态、上传文件是不是 UUID 重命名落盘。  
  
觉得有用就转给管上传和存储的同事——上传目录不给执行权限，比一百条后缀黑名单都稳。  
  
  
防御，不是在演练期间发现攻击，而是在演练开始前就把攻击面收敛到最小。
