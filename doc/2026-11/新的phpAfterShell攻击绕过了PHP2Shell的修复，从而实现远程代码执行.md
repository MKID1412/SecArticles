#  新的phpAfterShell攻击绕过了PHP2Shell的修复，从而实现远程代码执行  
原创 ZM
                    ZM  暗镜   2026-11-24 00:00  
  
一种名为 phpAfterShell 的新型 PHP 攻击会导致在易受攻击的服务器上执行未经身份验证的远程代码，即使这些服务器已经安装了针对 PHP2Shell 的 10 月份补丁。  
  
Depthfirst 的研究人员于 11 月 19 日披露了该漏洞，并演示了如何将其与 PHP 中的另一个漏洞结合使用，从而远程运行代码。该漏洞的编号为CVE-2026-126714，CVSS v4.0 评分为 9.2。缺陷在于 PHP 默认的基于文件的会话处理程序。会话允许 Web 应用程序在请求之间记住用户的登录状态、购物车或其他详细信息。启用上传进度显示后，PHP 可以在读取上传请求的同时打开并更新会话文件。由于此操作可以在应用程序启动之前完成，因此应用程序中的登录检查并不会阻止 PHP 执行相关代码。如果会话更新被中断，PHP 可能会留下一个包含新旧数据混合的文件。应用程序稍后在调用时可能会接受该文件作为有效文件session_start()。  
  
风险不仅限于错误的会话值。PHP 还可以根据存储的数据重建对象，这个过程称为反序列化。10 月份的修复并没有解决写入中断导致会话文件处于这种状态时会发生什么情况。正如网络安全新闻在其对 11 月份 PHP 安全更新的报道中所述，CISA 将之前 PHP2Shell 披露的两个漏洞添加到其已知可利用漏洞目录中。  
  
该列表适用于 10 月份的漏洞，而非 phpAfterShell。Depthfirst 的披露文档是对这种新攻击的研究演示，而非攻击者已在实际攻击中使用过该攻击的证据。  
  
10 月份的补丁限制了 PHP 在上传进度处理期间可以重建的对象范围。Depthfirst的技术分析表明，新的攻击方式有所不同。  
  
PHP 在应用程序稍后打开会话时（即在之前修复程序所涵盖的上传进度步骤之外），会接受损坏的会话文件。研究人员将这种行为与 PHP 内置类中的内存损坏漏洞结合起来，实现了远程代码执行。  
  
代码将以 PHP 工作进程的权限运行，但不一定拥有服务器的完全控制权。这些权限仍然可能使攻击者能够访问工作进程可以读取或更改的凭据、应用程序文件或客户记录。根据Depthfirst 的建议，将会话存储在 Redis 或数据库中而不是使用 PHP 的文件处理程序的应用程序不会受到此特定缺陷的影响。  
  
已修复的版本包括 PHP 8.2.36、8.3.37、8.4.28 和 8.5.13。10 月份的 PHP2Shell 更新不包含此修复。最初的 PHP 8 版本引入了命名参数和联合类型等特性，但 PHP 8.0 和 8.1 现已停止支持。仍在运行这两个分支的团队应迁移到受支持的版本。  
  
如果必须等待升级，depthfirst 建议session.upload_progress.enabled = 0在 Web 服务中进行设置php.ini并重新启动 PHP 工作进程。  
  
这会阻止研究人员描述的上传进度路由，但不会修复会话处理程序。打补丁后，请验证用于处理 Web 请求的版本，而不仅仅是检查命令行二进制文件。对于容器部署，请重新构建并重新部署应用程序镜像。  
  
如果 Linux 发行版提供了 PHP，请查看其提供的补丁软件包信息，因为其版本号可能与上游版本不同。
