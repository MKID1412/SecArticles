#  CMS漏洞-后台那个上传按钮比前台所有洞都值钱  
原创 围巢安全笔记

WEB 漏洞精讲 · CMS 篇  
  
有个站点，前台我试了半小时，注入没有、上传没有、越权也没有，差点就写"未发现高危"。  
  
  
后来顺手试了个弱口令进了后台，点开"外观 → 上传主题"，五分钟后我拿到了服务器权限。**不是 0day，是这系统本来就这么设计的。**  
  
  
这篇讲 CMS 的通用拿权限路径，约 2000 字，2 个干货。  
  
  
01｜CMS 为什么是重灾区  
  
CMS 就是"内容管理系统"，一套装好就能发文章的站。国内常见织梦（DedeCMS）、帝国、PHPCMS；国外三大是 WordPress、Joomla、Drupal；再加上几乎每个站在用的 phpMyAdmin。  
  
它的结构性问题是三件事叠在一起：  
- **后台功能太多。**  
模板编辑、文件管理、数据库备份、插件安装——每一项本质都是"让管理员改文件"，而管理员和攻击者在系统眼里是同一个人；  
  
- **插件质量参差。**  
主程序有人审，插件基本没人看。一个下载量几千的主题，可能就带着后门；  
  
- **更新滞后。**  
建站公司交付完就不管了，版本停在几年前，公开 exp 一搜一大把。  
  
所以打 CMS 的思路从来不是"找 0day"，而是**认出来是谁，然后翻它的历史账**  
。  
  
02｜先认脸：判断是哪个 CMS  
  
不用工具也能看个大概，几个特征很扎眼：  
  
干货**四个 CMS 的指纹特征**  
  
**WordPress**  
：路径里有 /wp-content/  
、/wp-admin/  
、/wp-json/  
；页面源码里带 wp-emoji  
 之类的痕迹。  
  
**织梦 DedeCMS**  
：后台路径 /dede/  
，版权区有"Powered by DedeCMS"，出错页会跳转并带特定提示。  
  
**Joomla**  
：/administrator/  
、/components/  
，还有 ?option=com_  
 这种参数。  
  
**phpMyAdmin**  
：登录页标题、/phpmyadmin/  
 或 /pma/  
 路径、index.php?route=/  
 这种 URL 风格。  
  
再说个容易忽略的：**看它的主题目录和模板文件名**  
。很多站换了皮但没换目录结构，目录名直接暴露血统。  
  
认出 CMS 之后，动作只有一步：**搜这个版本的历史漏洞，找现成的验证方式**  
。别现场逆向，浪费时间。  
  
  
03｜进了后台，有四条路通向服务器  
  
这才是 CMS 真正的价值所在。**后台不是"管理界面"，后台是"一个能改服务器文件的工具箱"**  
，四条路都通向同一个终点：  
  
**第一条，模板编辑。**  
WordPress 的"外观 → 主题文件编辑器"，织梦的"模板管理"，本质都是在线改 .php 文件。你把一段代码塞进某个会被访问的模板里，保存，然后打开对应页面——代码就执行了。

图 1｜WordPress 后台"外观 → 主题 → 上传主题"，红箭头是完整路径  
  
**第二条，主题/插件上传。**  
这条更省事：把带后门的文件打进主题压缩包，直接在后台"上传主题"，程序会自动解压到主题目录。**不需要你懂任何绕过，程序自己帮你把文件放好。**  
  
**第三条，文件管理器。**  
织梦后台有个"附件管理 → 文件式管理器"，就是一个网页版的文件浏览器，能新建、上传、改名、删除。这类功能本来是方便管理员传图片的，但它没有"只允许图片"的概念。  
  
![DedeCMS 后台文件式管理器](https://mmbiz.qpic.cn/mmbiz_png/8m3icSM3btkfjA5GIALbUGSj14hg6Ob8mLBjOByfTwsdcfGc6UkQqW67VQHbDZib0oxDryra1Cy0cwiafYRBRFXibsqY1FCxibCIfs3GMBobfMu8/640?wx_fmt=png&from=appmsg "")  
  
图 2｜DedeCMS 后台的文件式管理器，上传按钮就在底部  
  
**第四条，数据库写文件。**  
phpMyAdmin 这类工具给了你 SQL 执行权限，而 MySQL 本身就有"把查询结果写进文件"的能力——只要 secure_file_priv  
 允许、目录可写、路径猜得对，就能把内容写进网站目录。  
  
![phpMyAdmin 查询 secure_file_priv](https://mmbiz.qpic.cn/mmbiz_png/8m3icSM3btkeuwkmFJ8OGfbIvJxnFRUmXSCrEpvXXWicBPZ14KM0sfsXFj82hLhicCkfaEDD4aRbRdPwhRIdPAGajv2NuH1xYm9xic3FnYG85Ow/640?wx_fmt=png&from=appmsg "")  
  
图 3｜在 phpMyAdmin 里查 secure_file_priv  
，看这台机器让不让写文件  
  
干货**secure_file_priv 的三个值，决定你能不能写文件**  
  
NULL  
：完全禁止导入导出。看到这个值，写文件这条路直接断，别再试了。  
  
**某个具体路径**  
：只能往这个目录写。这时候要判断它和网站根目录是不是同一个，不是就没戏。  
  
**空字符串**  
：不限制，任意路径可写。这是最危险的配置，也是很多 phpStudy 类集成环境的默认值。  
  
查法就一句 SHOW GLOBAL VARIABLES LIKE 'secure_file_priv'  
。**先查再动手，能省一半时间。**  
  
  
04｜根子在"信任边界错位"  
  
这四条路的共同点是：**系统把"管理员"当成了绝对可信的角色**  
。一旦你是管理员，它就不再校验你输入什么——因为"管理员当然可以改文件"。  
  
问题是，管理员账号经常守不住：弱口令、复用密码、插件漏洞、备份文件泄露、甚至前台注入直接拿到 hash。**后台的强度，等于你最强的那个入口的强度。**  
  
所以评估一个 CMS 站点，不要只写"后台存在文件上传"，要写清楚链条：**从哪里进的 → 拿到了什么权限 → 能改哪些文件 → 最终影响到什么数据**  
。甲方看的是这个，不是功能列表。  
  
再往下走一步，才是 CMS 真正"值钱"的地方：**后台往往能读到整站的配置**  
。数据库账号密码、邮件服务口令、对象存储的密钥、短信接口的 AppKey，很多都写在配置文件里，而后台正好有"查看/编辑配置"的功能。拿到这些，你的影响范围就从"一个网站"扩到了"一套业务"。  
  
还有一个经常被当成"低危"的功能：**数据库备份与导出**  
。它会把整库导成一个文件，通常就放在网站目录下。你不用拿 shell，直接下载这个备份，里面就是全量用户数据——包括密码哈希。这个洞在报告里经常被写成"信息泄露（低危）"，实际危害比一个需要绕半天的上传高得多。  
  
判断版本也有小技巧，不用装工具：WordPress 看 readme.html  
 或者 /wp-json  
 返回里的版本字段；织梦看 /data/admin/ver.txt  
 这类版本文件；Joomla 看 /administrator/manifests/files/joomla.xml  
。**版本号是判断"能不能直接搜现成利用"的唯一依据**  
，比猜省事。  
  
再说入口。CMS 的后台入口十有八九不是靠"挖洞"进去的，而是**弱口令、默认口令、或者干脆没删的安装目录**  
。这三个都属于"配置问题"，但在实战里出现频率高得离谱——因为建站的人装完就走了，没人回头收拾。  
  
特别是**安装目录**  
。装完之后 /install/  
 还在，意味着有可能被重新走一遍安装流程，把数据库指向别处，或者直接把配置覆盖掉。这类问题在报告里常被写成"低危：目录未删除"，但它其实是"整站可被接管"的前置条件。  
  
所以完整的评估顺序应该是：**先看入口（弱口令/安装目录），再看后台功能（上传/模板/备份），最后看配置里泄露了什么**  
。三步走完，这个站点的风险画像就清楚了，不用一个个插件去试。  
  
05｜防守方今晚能做的四件事  
- **把后台从公网挪走**  
：改路径只是遮眼，加 IP 白名单或上 VPN 才是真的；  
  
- **关掉在线编辑**  
：WordPress 在配置文件里禁用文件编辑，这一条能直接掐死第一条路；  
  
- **上传目录禁止执行**  
：让上传目录里的 .php 不被解析，比任何后缀黑名单都可靠；  
  
- **数据库降权**  
：Web 连接数据库的账号不给 FILE 权限，写文件这条路就废了。  
  
第四条尤其值得做，因为它同时挡住了"数据库写文件"和"日志写文件"两种手法，成本只是一条授权语句。
